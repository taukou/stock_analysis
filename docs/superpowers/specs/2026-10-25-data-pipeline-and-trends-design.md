# 股市產業鏈：資料自動化與趨勢呈現 設計文件

日期：2026-10-25
狀態：草稿，待使用者確認

## 1. 目的與背景

這是使用者**自己看盤用**的工具（不是作品集展示、不是多人服務）。用 D3 把台股科技產業鏈畫成上／中／下游節點，點進節點看公司、點公司看側邊欄數據。

使用者目前的三個痛點（使用者原話）：
- 「資料沒有很完整」
- 「要一直手動處理事情」
- 「看不太出實際的趨勢」

使用者同意的處理順序：**先讓資料自動且完整地進來（地基），再把趨勢做到畫面上**。原因：資料不完整、不更新時，趨勢圖畫不出可信的東西。

## 2. 目標

1. 資料每天自動更新，使用者不需要手動跑任何腳本。電腦關機錯過的日子，下次執行自動補齊。
2. 上市＋上櫃公司都有股價、月營收、三大法人資料；缺資料就明確顯示「無資料」。
3. 畫面能看出一段時間的變化（個股與產業節點兩個層級）。
4. 系統會主動標出值得注意的訊號，使用者不必自己比數字。

## 3. 非目標

- 不做多人登入、權限、對外服務。
- 不做 K 線、技術指標、回測、下單。
- 此階段不搬到 GitHub Actions（之後再搬，但架構要讓搬遷不需重寫）。
- 不重做首頁 Shader 視覺與整體美術風格。
- 不改變「產業／節點／公司」的分類資料本身（由使用者維護）。

## 4. 反目標（做了也算失敗）

- 缺資料被當成 0 顯示或計算（例如營收年增率 0%、法人買賣超 0 張），使用者誤以為是真實數字。
- 股票代號被猜錯、默默寫入錯誤公司資料。
- 同步失敗但沒有任何跡象，畫面上看起來資料是新的、其實是舊的。
- 仍然需要使用者記得手動執行某支腳本才能讓資料正確。
- 金鑰再次出現在 git 中。

## 5. 限制與現況

- 技術：Python + Flask、Supabase（PostgreSQL）、D3.js v7、Windows 11 本機。延續現有技術，不換框架。
- 資料源：證交所（TWSE）、櫃買中心（TPEx）公開 API、FinMind（有 token，但有流量上限）。
- repo `taukou/stock_analysis` 目前**公開**，`.env`（SUPABASE_URL、SUPABASE_KEY、FINMIND_TOKEN）已在 git 歷史中，自第一個 commit 起外洩。使用者暫不改私人 repo，之後再改。
- 現有 `SUPABASE_KEY` 是 publishable（匿名）key，而同步腳本用它寫入 → 目前 RLS 很可能允許匿名寫入（成果報告聲稱已關閉公眾寫入，兩者矛盾，需實測確認）。
- 現有資料表（依成果報告 ERD）：`major_industries`、`value_chain_nodes`（含 `position_type`、`display_order`）、`companies`（`stock_id` PK、`market_type`、`latest_price`、`latest_change`）、`company_node_mapping`（`stock_id`,`node_id` 複合 PK）、`growth_momentum`（`stock_id`,`data_month` 複合 PK）、`smart_money_flow`（`stock_id`,`trade_date`）、`stock_history`（`id`,`company_id`,`trade_date`,`close_price`,`change_percent`,`volume`）、`industry_links`（`link_id`,`from_node_id`,`to_node_id`），及其他預留表。實際欄位以 Supabase 現況為準。

## 6. 已決定的做法

標記說明：**【使用者決定】** 為使用者明確同意；**【我的決定】** 為設計者判斷，使用者已看過描述並同意整體方向。

### 階段 0：金鑰處理【使用者同意】
- 到 Supabase、FinMind 後台作廢並重新產生金鑰（需使用者本人操作，實作者提供步驟）。
- `git rm --cached .env`、`__pycache__`，確認 `.gitignore` 生效；新增 `.env.example` 只列鍵名。
- 確認 RLS：匿名 key 只能讀；寫入改用 service role key，且只存在本機 `.env`（之後在 GitHub Secrets），絕不給前端。Flask 後端讀取用匿名 key 或 service key 皆可，但 service key 絕不能傳到瀏覽器。
- 不改寫 git 歷史（金鑰已作廢即無害；改寫歷史對公開 repo 也無法收回已被看過的內容）。【我的決定】

### 階段 1：資料地基

**自動執行（本地）**【使用者決定：先在本地跑】
- 新增單一入口 `run_sync.py`，依序執行所有同步步驟；單一步驟失敗不中斷其他步驟，最後回報摘要與非零結束碼。
- Windows 工作排程器：每天 16:00 執行，另加「使用者登入時」執行。【我的決定】
- **自動補跑**：每個資料集各自查資料庫最後日期，補齊到最近一個已公布的交易日；非交易日自然查無資料，跳過。
- 冪等：重複執行不產生重複資料（upsert + 複合唯一鍵）。
- 紀錄檔寫到 `logs/`（加入 .gitignore），保留近 30 天。
- 新增 `sync_runs` 表（或等效機制）記錄每次執行時間、各資料集最後日期、成功／失敗，供畫面顯示「資料更新到哪天」。
- 不依賴 Windows 特有功能，之後換成 GitHub Actions 只需加一份 workflow 檔呼叫 `run_sync.py`。

**網站自動啟動**【使用者決定】
- Windows 工作排程器「登入時」以 `pythonw` 背景啟動，用 waitress 跑 Flask，不跳出命令視窗；移除 `debug=True`。
- 只綁 `127.0.0.1`，不對區網開放。
- **不使用 5000 埠**（會和使用者其他專案衝突）。埠號由 `.env` 的 `APP_PORT` 設定，預設 `8765`（2026-10-25 檢查時未被佔用）。【預設值為我的決定】
- 啟動時若埠號已被佔用，寫入紀錄檔並結束，不改用其他埠。
- **不自動打開瀏覽器**，使用者自己點書籤。
- 伺服器紀錄寫入 `logs/`；附一個「重新啟動網站」的捷徑或批次檔。

**資料完整**【我的決定】
- 股價：改用 TWSE／TPEx 的「全市場單日行情」，一次請求取得當日所有公司；補跑時逐日請求。不再逐檔呼叫 FinMind。
- 三大法人：TWSE（現有 T86）＋ TPEx 對應的法人買賣超資料。
- 月營收：TWSE＋TPEx 的月營收資料（上市、上櫃各自的 open data）。
- 每日寫入 `stock_history` 一筆（收盤價、漲跌幅、成交量），`companies.latest_*` 由最新一筆衍生。
- **首次回填**：股價與法人至少回填 60 個交易日、月營收至少 13 個月（算得出 12 個月的年增率走勢）。若公開 API 拿不到歷史月營收，可用 FinMind 逐檔一次性回填，需能斷點續跑並處理流量上限。
- **存全市場**：股價、法人、月營收都寫入全部上市＋上櫃公司（約 1,800 家），不只 `companies` 表內的公司。之後新增公司時自動就有歷史資料，不需要逐檔回填。估算約 1,800 家 × 250 交易日 × 3 表，每年約數十 MB，在 Supabase 免費額度（500 MB）內；實作者需在回填後確認實際用量。【我的決定】
- 缺值存 `NULL`，不存 0；前端一律顯示「—」並不參與平均等計算。
- **既有的假 0 資料**：`growth_momentum`、`smart_money_flow` 現有資料無法分辨真 0 與缺值，全部刪除後由首次回填重新抓取。回填範圍以外的舊資料不保留（量少、且可信度不明）。【我的決定】
- **既有股票代號稽核**：一次性比對 `companies` 現有的 `stock_id` 與官方名稱，名稱不一致或代號非數字者列成清單給使用者確認後才修正；`company_node_mapping` 跟著同步修正。不自動改。【我的決定】
- 股票代號對應：只接受名稱精確比對；比對不到或多筆時輸出待確認清單（檔案或終端輸出），不寫入資料庫。
- `stock_history` 欄位命名與其他表不一致（`company_id` vs `stock_id`）：實作者可視情況統一，但需一次性遷移且不遺失資料。

**順手清理**【我的決定】
- 修 `database.py:21`（改 `!inner` 或改從 `value_chain_nodes` 查起），讓沒有公司的節點也能顯示。
- `/api/node_companies` 的查詢搬進 `database.py`，與其他查詢同一層。
- 刪除未使用檔案：`templates/industry.html`、`test.py`、`database.py` 的 `get_companies_by_node`（若重構後仍未使用）。`shader_test.html` 與路由保留與否由實作者判斷（不影響功能）。
- `requirements.txt`：移除未使用的 plotly、networkx，補上 requests，鎖定版本。
- `twse_sync.py` 改為共用 `database.py` 的 Supabase 連線。
- 前端 API 請求加上載入中與失敗提示。

### 階段 2：趨勢呈現【使用者決定：照設計者建議順序】

順序：**(1)+(5) → (2)+(3) → (4)、(6)、(7)**。

**(1) 側邊欄小圖表**
- 近 60 交易日收盤價折線。
- 近 12 個月營收年增率長條（正負分色）。
- 近 20 交易日投信、外資買賣超長條（單位：張）。
- 用 D3（已載入），不另加圖表函式庫。
- 缺資料的區間顯示斷點，不補 0。

**(5) 資料新鮮度**
- 頁面角落顯示「資料更新至 YYYY-MM-DD」（各資料集取最舊者或分別列出，實作者決定呈現方式）。
- 股價／法人資料落後最近交易日超過 1 個交易日 → 黃色提醒；同步最近一次失敗 → 紅色提醒。

**(2) 產業節點熱度**
- 六角形節點顏色深淺表示該節點旗下公司的平均漲跌幅（等權平均；缺資料公司排除）。
- 顏色延續台股慣例：紅漲綠跌。
- 節點旁顯示平均漲跌數字。

**(3) 時間區間切換**
- 今日／5 日／20 日 三個按鈕；切換後公司球與產業節點的顏色、數字都改為該區間累積漲跌幅。
- 區間漲跌幅 = 區間最後收盤 ÷ 區間起點前一日收盤 − 1，**使用還原股價**（見下方「除權息處理」）。

**除權息處理**【使用者決定】
- 同步時額外抓取 TWSE／TPEx 除權息資料（除權息日、現金股利、股票股利、參考價），存入新表。
- 漲跌幅、區間漲跌、產業熱度、訊號規則一律用**還原股價**計算；畫面上顯示的股價數字維持實際收盤價。
- 除權息當日的單日漲跌以「收盤 ÷ 除權息參考價 − 1」計算，不算成下跌。
- 明確標示除權息事件【使用者要求「額外再檢查是否除權息」】：
  - 側邊欄股價圖上，除權息日畫標記點，滑過顯示配發內容。
  - 當日或區間內有除權息的公司，公司球與側邊欄顯示「除息／除權」小標記。
  - 側邊欄列出近一年除權息紀錄。

**(4) 自動訊號標記**（初版規則，門檻可調）
- 投信連續買超 ≥ 5 個交易日。
- 營收年增率由負轉正（本月 > 0 且上月 ≤ 0）。
- 單月營收創近 12 個月新高。
- 當日成交量 ≥ 20 日均量 × 2。
- 在公司球旁顯示小標記，側邊欄列出觸發的訊號與依據數字。
- 資料不足（例如歷史不到 20 日）時不觸發，不以缺值推論。

**(6) 搜尋＋自選股**
- 搜尋框可輸入代號或名稱，跳到該公司所在節點並打開側邊欄。
- 自選股：點星號加入；清單集中顯示。只有使用者一人使用，存在瀏覽器 localStorage 即可。【我的決定】

**(7) 總覽畫面連線**
- 總覽時依 `industry_links`（from_node_id → to_node_id）畫出節點之間的供應關係線。若該表尚無資料，需提供填寫方式（使用者自行維護內容）。

## 7. 留給實作者決定

- 程式碼結構（是否拆 package、模組命名）。

## 8. 完成的樣子

- 使用者連續一週不碰任何腳本，每天打開網頁都看到前一個交易日的資料；中間關機兩天，開機後自動補齊。
- 隨便點一家上櫃公司，側邊欄三張圖都有資料。
- 總覽畫面一眼看出今天／近 20 日哪一段產業鏈最強。
- repo 中不再有任何金鑰，舊金鑰已失效。
